# CLI 业务流程实测：2026-10-25

使用 `dist/my-vm-cli.exe` 在 Windows 管理员会话中实测，未打开 GUI。基线为 `e8da579`；测试发现并修复两项既有缺陷，分别提交为 `e2e505e` 和 `d996ffe`。本报告记录实际覆盖范围，不代表所有客户机或硬件组合均已验证。

## 环境和测试资产

- HCS、`vmcompute`、HNS 可用；构建和自动检查使用 mise 管理的 Go 1.27.2。
- 原有 `win`、`ubuntu` 均处于关机状态。测试创建一台空白虚拟机，并复制两台已安装系统的虚拟机；另外创建两台用于磁盘链复制验证的临时副本。
- 所有测试机使用独立磁盘，关闭 GPU 共享、断开网络并清除宿主共享目录。客户机命令和文件复制通过 Hyper-V Socket 完成。
- Windows 克隆机分别使用原有代理和当前源码构建的代理复现文件传输故障；修复后的完整客户机流程使用当前代理。

## 修复及复测证据

### `e2e505e`：无共享目录的 Windows 虚拟机启动失败

启动流程始终监听客户机回传通道，但 HCS 配置此前只为 Linux 或存在共享目录的机器注册此通道。Windows 无共享目录时出现：

```text
启动客户机回传通道失败: listen hvsock ...: listen: An attempt was made to access a socket in a way forbidden by its access permissions.
```

改为始终生成该 Hvsock 服务的注册及原有安全描述符。配置回归覆盖 Windows 无共享、Linux 无共享、Windows 有共享；实际启动、暂停/继续、快照恢复和克隆启动均通过复测。

### `d996ffe`：大文件下载返回 `unexpected EOF`

约 1 MiB 文件上传成功，下载稳定返回 `unexpected EOF`；管理器日志同时记录 `客户机传输: unexpected EOF`。原代理和当前代理均可复现，小文件可成功。

删除客户机 HTTP 代理的 `DisableKeepAlives: true`，让管理器读完响应后再清理连接。保留内容长度和中断错误检查。修复后，以下每种文件均上传一次、下载三次，每次核对长度和 SHA-256：

| 字节数 | 三次下载结果 | SHA-256 |
| ---: | --- | --- |
| 1,048,598 | 全部一致 | `641440045982dac12d080dceab82a1b386dcc9ff7cb97a3e261810cb430d522e` |
| 10,485,797 | 全部一致 | `58150f5ce97f500ff1f5066789cb361e55624782c552fe6f1c05e8b8243e52df` |
| 67,108,883 | 全部一致 | `7fe9f9a8cd24e0c8ac78a3ef729ad832464a63321d069946bb560094f415a7d0` |

另增加真实 HTTP 截断响应回归：服务声明 1024 字节但只发送部分正文，`Client.CopyFrom` 必须返回 `io.ErrUnexpectedEOF`，保留已有目标文件且不泄漏临时文件。

## 限制和未通过前置条件

- Ubuntu 克隆机可以启动、暂停/继续、调整内存和正常关机，但客户机命令代理未连通。其成功执行命令、文件往返、输出和退出码、客户机文件内容回滚未完成，不能算作通过。本次没有通过图形桌面登录或重新安装 Linux 代理。
- 刚启动即请求正常关机，HCS 返回 `HRESULT 0x800710DF`；客户机启动完成后，相同批量关机流程通过。`--wait start` 等待的是虚拟机运行状态，不保证客户机操作系统已能处理关机或命令请求。
- 普通 `echo` 写入后立即在线快照，恢复时曾观察到文件不存在；改为 `FileOptions.WriteThrough` 与 `FileStream.Flush(true)` 后实际内容恢复通过。在线快照不包含 RAM，也不主动冻结文件系统或刷新应用缓存；不能据此承诺数据库等应用的一致性。
- 中文 Windows 程序的本地代码页输出在 JSON 文本字段中观察到乱码。ASCII 输出和 text 原始字节输出已验证；本轮未修改字符编码策略。
- 未验证 GUI/RDP 交互、GPU 共享、桥接流量、客户机 NAT 数据通信、共享目录实际读写或增强安装器界面。这些范围不能用本次 CLI 管理测试代替。
